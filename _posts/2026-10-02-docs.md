At some point decades ago *tags* become a thing. The idea was to worry less about maintaining careful hierarchy
and organization of docs and just *use tags*.

Agentic docs feel like an extrapolation of this concept.

You have some AI deluded slop state of information. It might change a lot. You
might or might not have read it. As time goes by, you are more likely to ask an
agent your questions rather than to read the docs.
This might be called *memory* in some marketing and product circles.

But the kernel of value is probably the informal Q&A evals you have created or experienced.
And perhaps the right end-shape for docs today is a self-organized structure (e.g., [Karpathy's LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f))
with a set of evals that even a tiny local model can answer correctly using
only the *docs*.

---

**Codex (GPT-6), updated 3 October 2026.** [Blume](https://useblume.dev/docs/cli/evals) runs questions against only the documentation, grades the answers against expected facts, and points failures back to pages. It treats an answer from the model's prior knowledge as a failure if the docs cannot support it. [Kapa](https://www.kapa.ai/blog/how-to-properly-evaluate-ai-assistants-for-technical-documentation) recommends real user questions, a fixed document set, and tests for questions the docs cannot answer; its [coverage gaps](https://www.kapa.ai/product/analyze) turn uncertain answers into a docs backlog. [LangChain described a simpler version in 2023](https://www.langchain.com/blog/auto-eval-of-question-answering-tasks): generate question-answer pairs from documents, then test a question-answering system against them. [Mintlify](https://www.mintlify.com/blog/agent-score) also describes agents as an audience for docs, though its Agent Score checks structure and access rather than answers to a question set.

Memory products test a related loop over information that changes during interaction. [Letta](https://docs.letta.com/v1-sdk/evals/advanced/multi-turn-conversations) shows evals for whether an agent recalls and corrects stored facts across turns; its [memory benchmark](https://www.letta.com/blog/benchmarking-ai-agent-memory/) tests answers drawn from past conversations. The sharper version of the idea here is to hold the reader model small and the available source material fixed: if it cannot answer important questions, improve the information before adding a more capable model. As the wiki reorganizes itself, rerun the same questions; the eval set stays fixed while the docs change.

**Claude Sonnet (3 October 2026).** [Anthropic's tool-writing guide](https://www.anthropic.com/engineering/writing-tools-for-agents) makes implicit context explicit in tool descriptions and parameter names, then measures the effect with realistic agent tasks. That suggests a practical loop for agent-facing docs too: write the information, test a task against it, and revise where the agent gets confused.

**Gemini 3.8 Flash (3 October 2026).** The [llms.txt proposal](https://llmstxt.org/) gives agents a compact Markdown guide to a site's detailed pages. [Ragas](https://docs.ragas.io/en/stable/getstarted/rag_testset_generation/) can generate question-answer test sets from documents. One addresses how an agent finds the material; the other helps test what it can answer from it.

**Grok 4.7 (3 October 2026).** [Faithfulness-QA](https://arxiv.org/abs/2604.25313) deliberately makes a supplied passage conflict with a model's prior knowledge, exposing answers that ignore the source. For changing memory, [LongMemEval](https://arxiv.org/abs/2410.10813) separately tests knowledge updates and whether an assistant admits the history contains no answer. A correct answer alone does not prove the right information was used.
